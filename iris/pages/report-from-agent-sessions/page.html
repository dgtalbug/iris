Current state

iris report --from-session <path> already exists — wired in src/cli.ts and implemented in src/commands/report.ts — but it only accepts a curated export: one .json, .md, or .txt file, or a directory whose filenames match SESSION_FILE_PATTERN. Nothing produces those files.

What agents actually leave on disk is JSONL, one record per line:

  • Claude Code: ~/.claude/projects/<cwd-slug>/<uuid>.jsonl
  • Codex: ~/.codex/sessions/<yyyy>/<mm>/<dd>/rollout-<timestamp>-<uuid>.jsonl

Pointed at either, the command fails before writing anything:

  • a session directory gives No supported session files found in ...; expected named JSON, Markdown, or text session artifacts, because the filename pattern anchors on .json|.md|.txt and .jsonl never matches
  • a single rollout file gives Unsupported session input format: ... (expected .json, .md, .txt, or a directory)

The extension guard is not the only blocker. parseDocument runs JSON.parse over the whole file, so a line-delimited transcript would still be rejected as malformed even if the guard let it through. Extraction is format-blind as well: stringsAtKeys sniffs generic keys (summary, content, message, path, command) rather than reading turn structure, and the key names do not line up. A Claude Code transcript records the repository as cwd and the branch as gitBranch on nearly every line, while ingestSessionSource looks for repo/repository/repo_path and branch/branch_name — so even a parseable transcript would report both as unspecified. And the generated envelope hardcodes agent: "other" and falls back to forty zeros for commit, discarding metadata the source already identifies.

So the backlog item is half built. The contract, the renderer, and sections.session_evidence are all in place; the reader cannot open the files that exist.

Proposed

Teach the existing ingestor the formats that are already on disk, and let it find them.

  1. JSONL reader. Accept .jsonl in both the file guard and the directory pattern, and parse line-delimited records into the document array instead of one JSON.parse. Skip malformed lines with a count rather than failing the import — transcripts are append-only and can end mid-write.
  2. Per-agent adapters. Read record structure instead of sniffing keys. A Claude Code transcript is typed line by line: user and assistant turns carry cwd, gitBranch, sessionId, and timestamp, tool calls live inside their message content blocks, and file-history-snapshot and file-history-delta records track edited paths directly. That is precisely the repository, branch, tool activity, and files-touched evidence the report contract already has fields for. Codex rollout files get their own adapter, and the existing key-sniffing path stays as the fallback for unrecognized shapes.
  3. Discovery. iris report --from-session with no path resolves the current repo to its session directory — Claude Code slugifies the cwd, Codex is date-partitioned — and picks the most recent transcript. An explicit --from-session <path> keeps working unchanged.
  4. Real envelope metadata. Set agent from whichever adapter matched, and take commit from repo HEAD at session end instead of defaulting to forty zeros.
  5. Redaction before render. Transcripts hold pasted secrets, file contents, and third-party data, and Iris output is HTML that gets published and exported. Summarize and redact by default; require an explicit flag to carry raw transcript text into session_evidence.

Step 1 alone makes the command usable against real files. Steps 2–4 are what make the resulting report worth reading. Step 5 is not optional once step 1 ships.
