## Context

See proposal.md. The measured constraint: from a `file://` page Chrome refuses `fetch` (`TypeError: Failed to fetch`) and `XMLHttpRequest` (`onerror`, `status 0`), because every local file is its own opaque origin. A classic `<script src>` still loads and executes in document order, which is how `mermaid.min.js` already works. That single exception is the only local-load mechanism available, so it is the one this change uses.

`spec-detail.ts` already produces the detail HTML per record; only its destination changes.

## Goals / Non-Goals

**Goals:**

- Collapse 30 generated files into one data file without losing any record content.
- Keep the index complete and honest when scripts do not run.
- Make it impossible for record content to escape the bundle.
- Reuse the existing mermaid re-render hook rather than adding a second mechanism.

**Non-Goals:**

- Bundling Work, Research, or contract pages. Those are published and exported, so they must stand alone without scripts.
- Client-side Markdown parsing. Rendering stays at generation time; the bundle carries already-rendered HTML.
- Lazy or chunked loading of the bundle.

## Decisions

### One global, JSON-encoded, with the unsafe sequences escaped

The bundle is `globalThis.IRIS_SPEC = {...};` where the value is `JSON.stringify` output with `<`, `U+2028`, and `U+2029` escaped as `<`, `U+2028`, `U+2029`. Escaping every `<` is the blunt instrument on purpose: it makes `</script>`, `<!--`, and `<script` alike inexpressible in the source text while decoding back to the original characters at runtime, so a record that legitimately shows `&lt;script&gt;` as escaped evidence still displays correctly. The line separators are escaped because they are valid JSON but invalid JavaScript string literals.

Alternative: a JSON file loaded by `fetch`. Rejected — measured as blocked on `file://`, which is the whole reason this design exists.

### Records are keyed by kind and name

Keys are `capability:<path>`, `change:<name>`, and `legacy:<slug>`, matching the three namespaces the previous per-file layout used. The hash route is `#/<kind>/<name>`, so an unknown or malformed hash simply matches no record and leaves the index displayed.

### The index owns both states

`spec.html` renders the index plus an empty detail region carrying a `<noscript>` explanation. The script shows one and hides the other; with no script the index stands alone and every row still prints its on-disk path, so the page degrades to a directory rather than to a blank frame. Injection uses `innerHTML` with content generated and escaped at build time, then dispatches the existing `iris:visibilitychange` event so Mermaid figures inside a newly shown record render through the current code path.

### Detail HTML keeps its own anchors

Record HTML retains the per-artifact id prefixes introduced by the previous change, so requirement anchors keep working inside the injected region and the table of contents resolves within the page.

## Risks / Trade-offs

- [Opening a record requires scripts] → Accepted for this section only, and stated on the page. The index — the part that answers "what exists" — needs no script.
- [One large data file replaces many small ones] → It is a single deterministic artifact keyed by record; agents can read the index for structure and grep the bundle for one record.
- [`innerHTML` injection] → Content is generated by Iris from already-escaped parser output; no untrusted string reaches the DOM unescaped, and inserted scripts do not execute by specification.
- [Bundle drift from the index] → Both are produced from one snapshot in one pass, and a test asserts every index row resolves to a bundle key.

## Migration Plan

1. Add the bundle builder and its escaping with tests, including a record containing `</script>`.
2. Emit `spec/data.js`, add the detail region and hash routing, and stop generating per-record pages.
3. Move tests from per-record files to bundle records; regenerate output and run the release gate.

Rollback: revert; stale `iris/spec/**/page.html` files are inert and the next render stops linking them.
