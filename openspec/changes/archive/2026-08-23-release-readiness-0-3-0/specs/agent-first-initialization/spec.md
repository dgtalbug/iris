## MODIFIED Requirements

### Requirement: managed skill preservation
The system MUST identify its generated skill content with verifiable managed ownership metadata and fail safely around user-owned or modified content. Ownership MUST cover every part of a generated surface that Iris authors, including the descriptive metadata an agent host reads before the managed content region, so that an upgraded Iris converges an already-installed surface on the current generated output instead of leaving stale metadata in place.

#### Scenario: managed content is intact
- **WHEN** a generated Iris skill has valid ownership markers and its managed content matches the recorded digest
- **THEN** initialization MUST update only that managed content and preserve user-authored bytes outside the managed boundary

#### Scenario: generated metadata is out of date
- **WHEN** a generated Iris skill carries valid ownership markers, its metadata outside the managed content region is provably the metadata Iris generated, and the current Iris release generates different metadata
- **THEN** initialization MUST replace that metadata with the current generated metadata, MUST report the surface as updated, and MUST leave every other user-authored byte unchanged

#### Scenario: generated metadata was edited
- **WHEN** the metadata outside the managed content region no longer matches what Iris generated
- **THEN** initialization MUST preserve that metadata, MUST NOT overwrite it with the current generated metadata, and MUST report the affected surface so the operator can reconcile it

#### Scenario: surface predates metadata ownership
- **WHEN** a surface generated by an earlier Iris release carries valid managed markers but no recorded metadata ownership
- **THEN** initialization MUST still recognize metadata that an earlier Iris release generated verbatim and refresh it, MUST record ownership for subsequent upgrades, and MUST preserve and report metadata it cannot attribute to Iris

#### Scenario: managed content was edited
- **WHEN** the managed content no longer matches its recorded digest
- **THEN** initialization MUST preserve the file and report an actionable collision instead of overwriting the edit

#### Scenario: target is unmarked or malformed
- **WHEN** the target skill file is user-owned, unmarked, partially marked, misordered, unsafe, or outside the repository boundary
- **THEN** initialization MUST not truncate, replace, or follow it and MUST report the affected surface

### Requirement: generated agent command surfaces

The system MUST generate typed command files for the supported agent surfaces from the same canonical Iris source that produces the skill, covering the frequent content actions, and MUST apply its managed-ownership rules to those files, including to the descriptive metadata each agent host reads before the managed content region.

#### Scenario: command surfaces are installed

- **WHEN** `iris init` installs agent guidance
- **THEN** it MUST generate one command file per supported content action into the Claude command directory and the GitHub prompt directory, each naming the exact Iris command, the file the agent edits, and the render step

#### Scenario: generated command content is refreshed

- **WHEN** a previously generated command file has valid ownership markers and its managed content matches the recorded digest
- **THEN** initialization MUST update only that managed content and preserve user-authored bytes outside the managed boundary

#### Scenario: generated command metadata is out of date

- **WHEN** a previously generated command file carries valid ownership markers, its metadata outside the managed content region is provably the metadata Iris generated, and the current Iris release generates different metadata
- **THEN** initialization MUST replace that metadata with the current generated metadata and MUST report the surface as updated, so an agent host never keeps describing a command by a description Iris no longer generates

#### Scenario: command file was edited or is user-owned

- **WHEN** a target command file is unmarked, partially marked, misordered, edited so its digest no longer matches, symlinked, or outside the repository boundary
- **THEN** initialization MUST preserve the file, MUST NOT truncate or follow it, and MUST report the affected surface

#### Scenario: unrelated command content exists

- **WHEN** a supported command directory already contains unrelated commands or prompts
- **THEN** initialization MUST leave that content unchanged
