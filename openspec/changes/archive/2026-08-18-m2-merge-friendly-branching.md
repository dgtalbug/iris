# M2 merge-friendly branching (archived)

- Proposed: establish a merge-friendly milestone workflow for this repo so the work can be merged incrementally and split into parallel branches without creating a large, hard-to-review change set.
- Applied: captured a milestone plan with explicit acceptance criteria, a narrow foundation branch from main for shared groundwork, a sequence for merging that branch first, and follow-on parallel branches by concern (for example CLI behavior, rendering/templates, tests/docs). The plan also calls for small merge-ready PRs, rebase-on-main discipline, and milestone archival once the work is complete.
